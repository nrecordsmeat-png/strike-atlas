# text-check

Проверка русского текста: дойдёт ли мысль до читателя и сохранился ли голос автора.

Что делает:
- **слепые пересказы.** Несколько моделей читают текст без контекста и пересказывают; по ним видно, какие мысли дошли, где читатели остановились и что перевели по-своему;
- **механика понятности.** Длина фраз и абзацев, длинные слова, связки, вопросы и обращения;
- **голос автора.** Сверка с эталоном, собранным из выгрузки Telegram: канала или переписки;
- **отчёт.** Один HTML-файл с инфографикой, открывается в любом браузере.

Чего не делает: не правит текст и не оценивает, прав ли автор.

## Два режима

**Зеркало** — пока текст пишется. Готового замысла не нужно: читатели пересказывают текст,
ты смотришь, что они увидели, и отмечаешь у каждого пункта «да, это», «не то» или «так лучше».
Где «не то», там и думать дальше. После правки можно прогнать новый круг.
Так мысль складывается из реакции на чужие прочтения.

**Проверка** — когда текст готов и ты знаешь, что хотел сказать. Видно, какие мысли дошли,
где читатели остановились и что перевели по-своему.

**Корни мысли** — дополнение к любому режиму. Claude ищет по философским и научным источникам,
откуда растут тезисы текста: где совпадает, где развивает, где расходится, а где мысль своя.
Это не проверка правоты. Пример: `examples/roots.json` → `roots.html`.

**Карта корней** — интерактивная страница для любого текста: слева текст с подсвеченными фразами,
справа график по времени. Щёлкаешь фразу — видишь, с кем из мыслителей она в родстве и в чём
совпадение или развилка; щёлкаешь мыслителя — находится фраза. Сверху сводка: сколько веков и традиций задето.
```
python scripts/roots_map.py мой_текст.txt roots.json --out карта.html
```
В карту встраивается весь текст. Если он личный, не выкладывай её публично.

## Сайт

Папка `site/` — страница для показа другим людям: галерея готовых разборов, механика текста прямо в браузере
(текст никуда не отправляется) и описание метода. Живого анализа на сайте нет: разборы делаются в чате
и выкладываются в `site/reports/` (файл отчёта + строка в `site/reports/index.json`).
Если для репозитория включены GitHub Pages, адрес страницы:
`https://nrecordsmeat-png.github.io/strike-atlas/tools/text-check/site/`.
Карта на сайте и карта из `roots_map.py` — один и тот же просмотрщик `viewer/roots_view.html`.
Для сайта отчёт сохраняется так: `python scripts/roots_map.py текст.txt roots.json --out карта.html --json-out site/reports/имя.json`.
В отчёт для сайта встраивается весь текст — выкладывай только то, что готов показать публично.

## Проверка инструмента

`python tests/run_tests.py` — контрольные тесты: ошибки входа, перенос отметок, перевёрнутая причинность,
тёзки в Telegram, пустые данные, разметка фраз. Полный синтетический пример со всеми полями — `examples/synthetic/`.

## Как пользоваться в чате с Claude

1. Дай Claude эту папку: приложи архив или ссылку на репозиторий.
2. Напиши «Зеркало по text-check» или «Проверка по text-check» и приложи текст.
3. Зеркало: получишь `зеркало.html`, откроешь в браузере, расставишь отметки,
   нажмёшь «Скопировать мои отметки» и вставишь в чат.
4. Проверка: Claude спросит замысел (можно попросить восстановить его за тебя), в конце будет `отчёт.html`.

Процедура для Claude описана в `SKILL.md`.

## Как запустить скрипты руками

Нужен только Python 3.8 или новее, без дополнительных библиотек.

Открой командную строку в папке `text-check`. В Windows: зайди в папку в Проводнике,
щёлкни по адресной строке, набери `cmd` и нажми Enter.

**Механика:**
```
python scripts/mechanics.py мой_текст.txt --json mech.json
```

**Эталон голоса.** Сначала выгрузи историю из Telegram Desktop: открой чат или канал →
три точки справа вверху → «Экспорт истории» → сними фото и видео → формат HTML или JSON.
Потом:
```
python scripts/voice.py build "путь\к\папке\выгрузки" --out profile_channel.json
python scripts/voice.py build "путь\к\папке\переписки" --author "Твоё имя как в Telegram" --out profile_chat.json
```
Эталон собирается один раз. Чем больше слов, тем лучше; меньше 20 000 — слабо.
Файлы эталона содержат частоты знаков и примет и словарь частых слов (только слова, встречающиеся не меньше 5 раз и минимум в двух блоках). Сам текст переписки не сохраняется. Эталон строится от 2 000 слов. Для переписки `--author` принимает имя или `from_id` из JSON-экспорта; в HTML-экспорте ID нет, и тёзок различить нельзя.

**Сверка текста с эталоном:**
```
python scripts/voice.py compare мой_текст.txt profile_channel.json --json voice.json
```

**Отчёт** (после того, как собран `readers.json` по образцу `examples/readers.json`; `mech.json` и `voice.json` — из двух команд выше, оба необязательны):
```
python scripts/report.py readers.json --mech mech.json --voice voice.json --out отчёт.html
```

## Ограничения

- Отметки понимания, пороги механики и пороги голоса — эвристики. Их соответствие тому, как понимают текст люди, не проверялось.
- Вопрос «что непонятно?» ловит только замеченные читателем трудности. Уверенно и ошибочно достроенная мысль в этот раздел может не попасть; её видно только при сверке пересказа с замыслом.
- Позиционные читатели — модели в заданной роли, а не реальные сторонники позиций.
- Отчёт можно перепроверить, только если к нему приложен протокол: сырые ответы читателей и основания отметок. Без протокола отчёт об этом предупреждает.

- Модели как читатели хорошо достраивают сжатый текст, часто лучше среднего человека.
  «Модели поняли» значит, что мысль в тексте есть и собирается, но не гарантирует, что её соберёт любой человек.
- Механика это счётное приближение к Гамбургской модели понятности. В оригинале модель опирается на оценки людей.
- Общий показатель похожести на автора (дельта Берроуза) на текстах короче ~2000 слов ненадёжен.
  Отдельные приметы (тире, кавычки, «ё», «ну») работают на любом объёме.

## Основа

- Kintsch & van Dijk (1978), Kintsch (1988): уровни понимания, макроструктура, модель «построение — интеграция».
- Iser, *The Implied Reader* / *The Act of Reading*: пробелы, которые заполняет читатель.
- Жинкин и русская психолингвистика текста: смысловое восприятие. Метод «встречного текста» — А. И. Новиков. Сравнение одинаковых перестроек у нескольких моделей-читателей — собственная процедура инструмента, а не метод Новикова.
- Langer, Schulz von Thun, Tausch, *Sich verständlich ausdrücken*: Гамбургская модель понятности.
- Burrows (2002): дельта для стилометрии.
