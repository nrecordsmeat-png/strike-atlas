# strike-atlas

Городской монитор Киева: Обзор, Карта, Данные и Методика. Статический сайт
GitHub Pages; `city_data.json` генерируется в uk-monitor и копируется без правок.
Старые адреса traffic/food/dynamics сохраняют перенаправления.

Полные исследовательские отчёты доступны на самом сайте в `reports/` без
доступа к приватному backend. Сохранены принятые Markdown-тексты, четыре
статические HTML-страницы, подробные агрегаты, протокол и манифест источников.
`reports/provenance.json` фиксирует исходные blob SHA. Сырые ответы не публикуются.
Ранний разбор помечен как предыдущая версия, чтобы не смешивать базы сравнения.
Пересборка HTML: `python3 scripts/build_reports.py` (нужен Pandoc).

Проверка клиентского кода без зависимостей:

```bash
node --test tests/client.test.mjs
```

Проверки запускают настоящий код страниц с небольшим адаптером DOM: история,
фильтры, сценарии, пустая выборка, ошибки загрузки, безопасный вывод источников,
пригодность аренды для сравнения и качество наблюдений. Они не заменяют проверку
раскладки в браузере. Контракт модели и серверные тесты — в uk-monitor.

Повторяемые сценарии используют сохранённый срез в `tests/fixtures/city_data.json`.
Свежий `city_data.json` проверяется отдельно: новые наблюдения могут законно
изменить числа и состояния, сохраняя правила отображения.

## Тестовый обзор функций

`functions-test.html` — отдельный экран с календарём сведений по услугам,
источниками выбранного эпизода и учебной шкалой восстановления. Ссылка есть
в основном обзоре. По умолчанию открыт реальный реестр; учебные данные имеют
явное обозначение и отдельный переключатель. Общий процент активности города
не вычисляется: охват и объём использования ещё не измерены.

Шкалу `scenarios[].timeline` считает backend через рабочую модель на каждом
моменте публикации и устаревания. Контракт — `uk-monitor/docs/function_monitor.md`.
Клиентские регрессии используют сохранённый городской срез и отдельные
учебные `tests/fixtures/function_scenarios.json`; свежий снимок проверяется
отдельно. Старый снимок без шкалы и ошибка загрузки обозначаются явно.
`tests/layout.html` открывает этот же экран в настоящем iframe шириной 390
или 1140 CSS px для ручной проверки раскладки без изменения окна браузера.

Индекс встроен во вкладку «Активность» основного обзора: `./#activity`.

Обзор и индекс используют собственные
даты; при открытии вкладки общий календарь обзора скрывается. Встроенный экран

`tests/layout.html?page=activity` проверяет полный расчёт в iframe 390/1140 CSS px;

38 клиентских проверок; backend — 95. Публикуется только `city_data.json`

- Контекст удара не подтверждает доступность услуги; главная говорит о сообщениях,

- История скрывает будущее восстановление, сутки считаются по времени Киева.

## Карточка жителя «НовГор»

`novgor-card.html` — публикационная копия единственной рабочей карточки,
выбранной пользователем 23.10.2026 в PR №34 репозитория novgorod.
Источник правок: `novgorod/research/character-card/experiments/card.html`.
После изменения исходника сюда копируется весь файл; самостоятельную версию
карточки в этом репозитории не развивать.

В редакции из [novgorod PR №41](https://github.com/nrecordsmeat-png/novgorod/pull/41)
подключена личная сцена Б3: кнопка «Сцена Б3» или `novgor-card.html#b3`.
Предложение знакомства, выбор и встреча исполняются общей моделью;
доступные игроку сведения отделены от скрытого состояния. Условия сцены
меняются в режиме разработчика с перезапуском, не переубеждением в партии.

В [novgorod PR №42](https://github.com/nrecordsmeat-png/novgorod/pull/42)
добавлен первый исполняемый телесный цикл. Панель «Жизнь двора: расчёт тела»
запускает питание, питьё, нужду и помощь для трёх жителей. Запасы и время
помощника расходуются; последствия показываются в здоровье и истории.
В первом пакете сон, среда, болезни и возрастные процессы ещё не рассчитывались;
численные настройки телесного расчёта предварительные.

В [novgorod PR №45](https://github.com/nrecordsmeat-png/novgorod/pull/45)
обычный телесный опыт получил явно обозначенное внешнее снабжение.
Ограниченный запас без пополнения включается отдельно для проверки истощения;
остатки и условия снабжения видны рядом с управлением временем.
Добыча и производство пока не рассчитываются; физические параметры тела
этим исправлением не менялись.

В [novgorod PR №46](https://github.com/nrecordsmeat-png/novgorod/pull/46)
добавлен первый медицинский случай раны с осложнением. Исполняются течение
болезни, осмотр и лечебный пакет; расходуются время знахарки, вода, средства
и повязки. Сравнение с ошибочной версией показывает разные последствия помощи.
Карточка связывает известное событие, наблюдаемые признаки, ограничения и
датированную версию знахарки. Истина остаётся в диагностике, недоступные
осмотры не раскрываются возвращением наблюдателя. Декоративные поля убраны
из здоровья, история медицинских событий входит в рубрику «тело».
Это один тип причины с опытными числами; остальные болезни, хронизация,
заражение и полноценное заживление травм пока не реализованы.

В [novgorod PR №47](https://github.com/nrecordsmeat-png/novgorod/pull/47)
блок потребностей разделяет наблюдаемое состояние и фактическую суточную выдачу.
Показаны доли личной нормы, состав и допуск пищи, результат естественной нужды
и конкретные препятствия. Уход раскрывается до действий и исполнителей;
у помощника видны получатели помощи и затраченная доля дня. Недоступные
суточные сведения не появляются при возвращении наблюдателя. Физиологические
параметры и канон не изменены.

В [novgorod PR №48](https://github.com/nrecordsmeat-png/novgorod/pull/48)
исправлено отсутствие голода и жажды в обычной карточке: блок потребностей
теперь находится в начале здоровья и не требует запуска телесного опыта.
Сведения снимка и живого расчёта имеют соответствующую дату; неизвестная
выдача не подменяется нулём.

В [novgorod PR №49](https://github.com/nrecordsmeat-png/novgorod/pull/49)
подключены личные возрастные нормы еды и воды и исправлен повторный множитель
количества во входе полезности. Зубной приступ проходит через осмотр, выбор
помощи знахаркой, расход времени и средств, удаление и самостоятельное течение
воспаления. Потеря зуба меняет фактический допуск еды; доставка мягкой пищи
исправляет недокорм при полном запасе сухарей. Точное число имеет доступный
источник и дату, скрытая история не раскрывается обновлением счёта.
Пороговые значения и ставки остаются опытными; грудное кормление и весь род
не объявляются подключёнными к телесному расчёту.
Проверенный [исходник](https://github.com/nrecordsmeat-png/novgorod/blob/b75aa10d54f252fcf87e737162020dc8a5069961/research/character-card/experiments/card.html).
